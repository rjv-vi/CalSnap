# Вклад в CalSnap

Спасибо, что хочешь помочь! Это маленький pet-проект, поэтому правила
короткие.

## Как сообщить об ошибке

1. Проверь, что бага ещё нет в [Issues](https://github.com/rjv-vi/CalSnap/issues).
2. Открой новый issue с шагами воспроизведения, ожидаемым и фактическим
   поведением, скриншотом и информацией о браузере/ОС.
3. Если можешь — прикрепи логи из встроенной dev-панели (5 быстрых тапов по
   логотипу 🍎 на экране «О приложении» → `📋 Скопировать логи`).

## Как предложить фичу

Открой issue с тегом `enhancement` и опиши пользовательский сценарий:
*кому, в какой ситуации и зачем* эта фича нужна. UI-мокапы приветствуются.

## Как прислать PR

1. Форкни репо и создай ветку от `main` (`feat/short-name` или `fix/short-name`).
2. Не подключай новые npm-зависимости и не вводи бандлеры — стек намеренно
   простой: pure HTML/CSS/JS, всё хостится на GitHub Pages «как есть».
3. Открой `index.html` через любой статический сервер
   (`python3 -m http.server 8080`) — `file://` ломает Service Worker и AI.
4. Соблюдай существующие стилевые соглашения:
   - 2 пробела для отступов в HTML/CSS, 2 пробела для JS
   - короткие имена для часто используемых хелперов (`G/S/U/log/key/...`)
   - не добавляй комментарии «что» делает код — оставляй комментарий только
     на «почему», если это неочевидно
5. Все строки UI пиши через `data-i18n` / `t()` / `tf()`. Английский
   перевод обязателен — добавляй ключ в обе ветки `I18N` в
   `assets/js/i18n.js`.
6. Service Worker: при изменении кэшируемых ассетов — подними версию
   `CACHE` в `sw.js` (например, `calsnap-v8` → `calsnap-v9`).
7. Проверь, что приложение продолжает работать офлайн (DevTools → Network
   → Offline) и что онбординг проходит без ошибок в консоли.

## Стиль коммитов

Без жёсткой схемы, но желательно в духе [Conventional Commits](https://www.conventionalcommits.org/):

```
feat(water): add 1L bottle preset
fix(sw): bump cache version after icon swap
docs: clarify Gemini API key setup
```

## Релиз Android-сборки

Полная инструкция в [ANDROID.md](./ANDROID.md). Кратко: ставишь semver-тег
`vX.Y.Z`, GitHub Actions сам собирает APK + AAB и публикует Release.
